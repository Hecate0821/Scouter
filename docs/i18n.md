# 界面文字与多语言

代码里不写任何给人看的文字，只写 key；文字放在 `locales/<语言>/<命名空间>.js` 里。数据点库的文字是内容，原文写在 `data/*.json`，别的语言的译文放在 `locales/<语言>/data.js`。加一种语言 = 复制一份 `locales/zh/`，逐条翻译，不用动代码。现在有中文（`zh`，源文字）和英文（`en`，`locales/en/` 是完整的译本，`data.js` 里是数据点库的译文）。

## 怎么用

```js
t("infer.kpi.tpot")                                   // 纯文字
t("infer.analysis.eager", { n: fInt(r.nKern), us: g.launchUs, total: V(fT(x)) })   // {n} 这类占位符换成参数
```

```html
<h3 data-i18n="arch.rack.h3"></h3>                       <!-- textContent -->
<span data-i18n-html="shell.ctl.glob.etaC"></span>       <!-- innerHTML，值里可以有 <b>、<sub>、<a> -->
<input data-i18n-attr="aria-label=appendix.data.attr.rel-q.aria-label;placeholder=appendix.data.attr.rel-q.placeholder">
```

`I18N.apply(document)` 在 `src/ui/app.js` 开头把这些属性填好；之后由 JS 渲染的部分都在渲染时调用 `t()`。

计算核心（`src/engine/`）不调 `t()`，也不依赖 i18n：它返回消息 `Msg.of("engine_train.op.lm", 参数)`。界面启动时设 `Msg.render = m => t(m.key, m.p)`（`src/ui/base.js`），消息在拼进字符串时才变成文字；参数也可以是消息。Node 里不设，消息保持为 key（见 [engine.md](engine.md)）。

## 文件与命名空间

一个命名空间对应一个文件，`I18N.add("zh", "<命名空间>", {...})` 里的 key 会自动加上 `<命名空间>.` 前缀。

| 命名空间 | 放什么 |
|---|---|
| `shell` | 页头、导航、全局参数栏（index.html） |
| `common` | 共用的格式、图表、状态、单位、瓶颈标签（`src/ui/base.js`、`state.js`、`charts.js`、`app.js`） |
| `overview` | 总览（`src/ui/overview.js` 和对应 HTML） |
| `arch` | 模型架构页：模型总览、模块 roofline、跨模型对比、模型参数编辑（`src/ui/arch.js`、`archviz.js`、`state.js` 里的编辑器） |
| `train` `par` `calib` `comm` | 后训练：一个 step、并行、和实测对照、一层里的通信 |
| `infer` `tradeoff` `spec` `config` | 推理：一步、部署取舍、投机解码、引擎 / 训练预设（`src/ui/config.js`） |
| `quant` `rl` `appendix` `releases` | 低精度、RL、附录、发布摘要 |
| `engine_common` `engine_infer` `engine_train` `engine_par` `engine_quant` | 计算核心返回的消息：算子名、通信名、警告、模型说明（`src/engine/*.js`） |
| `data` | 数据点库文字的译文（覆盖 `data/*.json` 里的字段，见约定 6） |

## 约定

1. **整句一个 key。** 不要把翻译过的碎片拼成句子（语序在别的语言里会变）。带可选从句的句子：把从句做成单独的 key，作为参数传进去。
2. **数字在代码里格式化。** `fN`、`fT`、`fB` 等格式化后作为参数传入；值里不写计算。
3. **HTML 只出现在会进 innerHTML 的值里**，并且只用 `<b> <i> <sub> <sup> <code> <small> <a> <br>`。会进 textContent 的值不能带标签。
4. **函数值尽量不用。** 只有占位符表达不了的语法（复数、按条件换词序）才写成 `p => ...`。和语言有关的排版规则（比如模型名怎么缩短：`common.fmt.shortName`）也写成函数值放在 locale 里；代码不按显示出来的文字做判断。
5. **代码里只写和语言无关的 token：** 数字、单位；代码标识符（带数字或 `_ / . =` 的，如 `o_proj`、`--tp-comm-overlap`、`fp8`）；缩写（没有小写字母的，如 TP、GEMM、BF16）；CamelCase 的名字（SGLang、NVLink、MoE）；引擎表里的名字（模型、GPU、引擎、kernel、格式、CP / EP 方法）；以及 `tests/i18n.js` 里 `NAMES` 列出的少数专名（torchtitan、Megatron、Blackwell、dgrad……）。其余的词都走 key，哪怕中文页面也照写英文（decode、expert、workspace、dense FFN）：zh 的值就写英文原词，别的语言才改得动。计算核心同样：算子名、通信名都是消息，输出里的普通字符串只能是标识符或表里的名字（`tests/engine.js` 检查）。
6. **数据的译文走覆盖层。** `data/*.json`（生成 `src/data/db.js`）是内容，原文写在里面。别的语言在 `locales/<语言>/data.js` 里登记译文：记录的字段 `"<记录 id>.<字段>"`，数组字段的一项 `"<记录 id>.<字段>.<序号>"`，数据集的字段 `"<数据集 id>.<字段>"`，指标名 `"<数据集 id>.metrics.<指标>"`。`localizeData()`（`src/ui/base.js`）启动时把译文换进数据点库；没登记的字段保持原文。
7. key 用小写驼峰、点分层：`<区域>.<对象>[.<细分>]`，比如 `kpi.tpot`、`analysis.specCap`、`table.ledger.head.k`。从 HTML 自动抽出来的 key（`b2.lede`、`tbl.row3.c2` 这类）保持原样即可，不必改名。

## 加一种语言

1. 在 `src/i18n/i18n.js` 的 `LOCALES` 里登记，比如 `en: { name: "English", html: "en" }`。
2. 复制 `locales/zh/` 为 `locales/en/`，把每个 `I18N.add("zh", ...)` 改成 `I18N.add("en", ...)`，逐条翻译。漏翻的 key 自动退回中文。`data.js` 里登记要翻的数据文字（可以先空着）。
3. 打开 `index.html?lang=en`；页头会出现语言选择。`cd tests && npm run i18n` 检查。

## 检查

```
cd tests
npm run i18n                                   # 两种语言各跑一遍，见下（--lang=zh / --lang=en）
node snapshot.js ../index.html new.json base.json   # 只搬文字、不改内容时，渲染出来的文字应当和 base.json 完全一样
```

`tests/i18n.js` 查四件事：

1. `src/` 和 `index.html` 里没有中日韩文字，用到的 key 都存在，`data.js` 的每个 key 都对得上一条记录的文字字段；
2. 代码不按显示文字分支（不拿中文 / 全角标点 / × 去比较、split、replace、匹配正则）；
3. 每个模型 × 引擎 × 阶段 × 框架渲染每一页，没有缺失的 key；
4. 英文页（`--lang=en`）上不剩中文：界面、数据点库里的中文都要有译文；语言菜单里的“中文”除外。另外 `locales/en/` 和 zh 的 key 必须一一对应（缺的会悄悄退回中文，多的是打错了名字）。
5. 伪本地化：渲染时 locale 的每个值包进 `⟦ ⟧`、数据点库的文字包进 `⟪ ⟫`，标记外面剩下的词就是代码写死的、翻译够不到的文字；只要出现约定 5 以外的词就报错，列出词、页面和所在的那段文字。
